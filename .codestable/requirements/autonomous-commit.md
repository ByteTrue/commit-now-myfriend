# 让 AI 自动整理本地改动并创建提交

## 用户故事

- 作为一个已经信任当前改动范围的开发者，我希望一条命令让 AI 整理提交，而不是每一步都停下来确认。
- 作为一个工作区里有几组独立改动的人，我希望工具能在安全时拆成多个本地提交，而不是把所有事情塞进一个 commit。
- 作为一个在脚本或非交互环境里使用工具的人，我希望输出稳定、可读或可解析，而不是强行打开全屏界面。
- 作为一个担心误操作的人，我希望自动流程只创建本地提交、不推送，并在冲突或疑似凭证出现时停下来。

## 为什么需要

有些提交不需要完整的人工审阅流程：改动范围清楚、目标明确，只想快速得到合理的提交分组和信息。完全手写提交信息会打断节奏，但完全放开又有风险。Autonomous Commit 给用户一个更快的路径，同时把危险边界收紧。

## 怎么解决

运行 `cnm auto` 后，AI 根据当前选中的本地改动规划并创建一个或多个提交。用户可以用参数收窄提交范围；流程会使用受限的本地提交能力完成工作，最后报告结果。遇到需要人工判断的冲突、疑似凭证或不能安全完成的情况时，它会失败并说明原因，而不是继续猜。

## 边界

- 不 push 到远端，只创建本地提交。
- 不做逐步确认；需要逐步审阅时使用 Interactive Commit。
- 不在非交互流程里修复冲突；冲突修复必须进入 Full-screen TUI。
- 不绕过 secret blocker，也不静默跳过含疑似凭证的选中改动。
- 不运行项目测试、lint 或任意检查；Git hooks 可以失败并阻止提交。
