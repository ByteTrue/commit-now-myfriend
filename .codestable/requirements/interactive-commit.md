# 在全屏终端界面里审阅并创建提交

## 用户故事

- 作为一个正在整理一组本地改动的开发者，我希望先看到这次会提交哪些文件和 diff，而不是盲目让工具直接提交。
- 作为一个想让 AI 帮忙写提交信息的人，我希望能看见 AI 的计划并在提交前改掉不满意的分组或措辞。
- 作为一个工作区里同时有多件事的人，我希望在提交前能收窄提交范围，而不是把不相关改动一起带进去。
- 作为一个遇到提交阻塞的人，我希望在同一个界面里确认是否进入修复，而不是让工具在后台静默改代码。

## 为什么需要

写 commit 最费时间的地方不是敲 `git commit`，而是判断哪些改动该放在一起、提交信息该怎么表达、有没有把不该提交的东西混进去。纯命令行确认太碎，完全自动又让人不放心。Interactive Commit 给开发者一个可以停下来审阅和调整的地方。

## 怎么解决

运行 `cnm` 后，用户在全屏终端界面里查看提交范围、diff、AI 活动和提交计划。AI 可以帮忙规划分组和消息，但真正产生提交前，用户可以给指令、接受、编辑或重新调整。遇到需要人工判断的修复场景时，界面会让用户显式确认。

## 边界

- 不负责无确认地自动提交；想要快速自动执行应使用 Autonomous Commit。
- 不把 commit split 或 repair 做成独立入口；它们是提交流程里的能力。
- 不运行项目测试、lint 或任意检查；这些留给用户自己的命令和 Git hooks。
- 不在非交互环境里强行打开全屏界面；脚本和机器可读输出应走对应的非 TTY 行为。
